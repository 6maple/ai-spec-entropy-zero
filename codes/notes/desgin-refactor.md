# 方案三重构细化（产品 + 体验 + 前端实现）

## 0. 文档定位

本方案用于将“闭卷复习”能力从“概念重复入口”升级为“单篇精练 + 全站综合复习”的双层体系。

- 笔记详情页的“闭卷复习”：服务当前单篇笔记的即时自测。
- 顶部导航的“全部复习”：服务跨笔记、跨主题的连续复习与进度追踪。

目标是不做无效大重构，在现有信息架构上完成清晰分工与体验升级。

---

## 1. 产品目标（Why）

### 1.1 核心目标

1. 消除“两个闭卷复习入口语义重复”的认知冲突。
2. 建立“学习 -> 单篇自测 -> 全站复习”闭环。
3. 提升复习效率与可持续性（连贯刷题、可见进度、低操作成本）。

### 1.2 成功指标（建议）

1. 导航点击后进入复习的转化率提升。
2. 单次复习会话平均答题张数提升。
3. 日活用户中有复习行为的占比提升。
4. “复习功能理解困难”的反馈显著下降。

## 2. 信息架构（IA）

### 2.1 顶部导航

- 开卷笔记（/）
- 全部复习（/cards）

说明：将原“闭卷复习”文案统一改为“全部复习”。

### 2.2 页面职责分层

1. 笔记详情页（/notes/:slug）
   - 开卷笔记：知识内容阅读。
   - 闭卷复习：仅当前笔记卡片的快速自测。

2. 全部复习页（/cards）
   - 聚合全站卡片。
   - 提供筛选、排序、连续复习与进度反馈。

---

## 3. 用户任务流（User Flow）

### 3.1 流程 A：学完立即测（单篇）

1. 用户在笔记详情阅读开卷内容。
2. 点击“闭卷复习”切换。
3. 完成当前笔记卡片自测。
4. 可跳转“全部复习”进入综合巩固。

体验目标：切换成本低、上下文不断裂。

### 3.2 流程 B：日常刷题（全站）

1. 用户从导航点击“全部复习”。
2. 设置筛选条件（标签/笔记来源/难度）。
3. 点击“开始复习”。
4. 在连续播放器中刷题，实时看到进度。
5. 完成后看到会话结果摘要。

体验目标：启动快、连续性强、结果可感知。

## 4. 功能规格（What）

### 4.1 导航与命名

1. 顶部导航文案：闭卷复习 -> 全部复习。
2. 导航高亮逻辑不变：/cards 归属“全部复习”。
3. 图标建议：ListChecks 或 PlayCircle（表达“流程化复习”）。

### 4.2 笔记详情页（保留并微调）

1. 保留“开卷笔记 / 闭卷复习”切换。
2. 闭卷模式只加载当前 note 对应 cards。
3. 增加一个轻量跳转入口：“去全部复习”。

微文案建议：

- 闭卷复习说明：仅练当前主题
- 跳转按钮：去全部复习（跨主题）

### 4.3 全部复习页（重点升级）

#### 4.3.1 预备区（开始前）

1. 数据概览：可复习卡片总数。
2. 筛选器：
   - 标签（多选）
   - 来源笔记（多选）
   - 题型（qa/fill_in_blank/error_correction）
3. 排序策略：
   - 随机
   - 按最近未复习优先
   - 按难度优先（后续可接）
4. 行动按钮：开始复习。

#### 4.3.2 进行区（复习中）

1. 使用现有 CardPlayer 作为核心交互。
2. 顶部展示会话进度：第 X / Y 张。
3. 保留“显示答案与语义关联”。
4. 提供“下一张 / 结束本轮”。

#### 4.3.3 结果区（完成后）

1. 本轮复习完成提示。
2. 展示关键指标：完成张数、耗时、覆盖主题数。
3. 提供二次行动：
   - 再来一轮（同配置）
   - 调整筛选再开始

## 5. 交互与 UX 细化（How）

### 5.1 一致性原则

1. “学习模式”与“复习模式”颜色语义区分，但组件结构一致。
2. 同一类动作位置固定（主按钮右侧、次按钮左侧）。
3. 所有关键操作有即时反馈（状态文案 + 按钮状态）。

### 5.2 降低认知负担

1. 页面副标题明确回答“这里是做什么的”。
2. 首屏只保留必要控件，进阶筛选放在可展开区域。
3. 空状态给出下一步指引，不出现死路。

### 5.3 空状态设计

1. 无卡片数据：提示“暂无可复习卡片”，附“返回笔记库”。
2. 筛选后为 0：提示“当前筛选无结果”，附“清空筛选”。

### 5.4 键盘与可访问性

1. 支持空格翻卡（后续迭代可开关）。
2. 关键按钮支持 Enter 激活。
3. 交互控件具备 aria-label。

### 6.2 建议新增状态模型（最小可行）

```js
reviewSession = {
  scope: 'single' | 'global',
  filters: {
    tags: [],
    noteSlugs: [],
    cardTypes: [],
  },
  order: 'random' | 'by_unreviewed',
  cards: [],
  currentIndex: 0,
  startedAt: number,
  finishedAt: number | null,
};
```

说明：

- single 用于详情页闭卷。
- global 用于 /cards 综合复习。

### 6.3 数据层改造建议

在 dataService 增加聚合能力，不改变现有读取协议。

建议新增函数：

1. getAllCardsWithMeta()
   - 返回全量卡片并附带来源 note 元信息。
2. filterCards(cards, filters)
   - 客户端筛选函数。
3. sortCards(cards, order)
   - 客户端排序函数。

输出结构建议：

```js
{
  (cardId,
    noteId,
    noteSlug,
    noteTitle,
    tags,
    cardType,
    question,
    answer,
    explanation);
}
```

### 6.4 页面与组件职责

1. CardsPage
   - 管理筛选配置与会话生命周期。
   - 将卡片数据传给 CardPlayer。

2. CardPlayer
   - 专注卡片展示与答题交互。
   - 不负责请求和筛选。

3. NoteDetailPage
   - 保持单篇上下文。
   - 仅在“闭卷复习”时组装当前笔记卡片。

### 6.5 路由策略

当前保持不变：

- /cards 作为全站复习入口。
- /notes/:slug 保持单篇上下文。

可选增强：

- /cards?from=note&slug=xxx 用于从详情页带条件跳转。

## 8. 视觉与布局建议

1. 顶部保留统一导航高度与结构，避免模式切换导致跳动。
2. /cards 首屏采用“配置区 + 启动按钮 + 数据概览”的轻仪表盘布局。
3. 复习中页面聚焦卡片本体，降低外围视觉干扰。
4. 暗黑模式下维持同等对比度，尤其关注按钮禁用态可辨识性。

## 9. 迭代计划（分阶段）

### Phase 1（快速落地，1-2 天）

1. 导航文案改为“全部复习”。
2. /cards 增加基础筛选与开始复习流程。
3. 复习完成后展示最小结果摘要。

验收：用户可在 10 秒内从首页进入复习并完成一轮。

### Phase 2（体验增强，3-5 天）

1. 增加排序策略与筛选记忆（LocalStorage）。
2. 增加从详情页跳转到 /cards 的预置条件。
3. 增强空状态与异常提示。

验收：连续复习流程中断率下降，重复配置次数减少。

### Phase 3（算法升级，可选）

1. 接入间隔重复算法。
2. 增加学习统计视图。
3. 支持个性化复习计划。

验收：7 日复习留存和完成率有稳定提升。

---

## 10. 验收标准（DoD）

1. 用户能清晰区分“单篇闭卷”和“全部复习”。
2. /cards 支持至少 2 类筛选 + 1 类排序。
3. 复习流程完整：开始 -> 作答 -> 完成 -> 结果反馈。
4. 空状态、无数据、加载失败均有明确可执行提示。
5. 桌面与移动端均可正常使用核心流程。

---

## 11. 风险与规避

1. 风险：筛选维度过多导致首屏复杂。
   - 规避：默认只展示高频筛选，其余折叠。
2. 风险：全量卡片聚合后首屏加载变慢。
   - 规避：先加载索引，再按需加载卡片内容。
3. 风险：用户对“全部复习”理解偏差。
   - 规避：副标题与引导文案强调“跨主题连续复习”。

---

## 12. 结论

方案三的最佳落地方式不是“简单改名”，而是建立双层复习心智：

- 笔记详情页闭卷复习：即时巩固当前主题。
- 全部复习页：系统化、连续化、可追踪的长期复习。

在当前项目架构下，可用最小改造达成高价值体验升级，并为后续算法化学习系统预留空间。
