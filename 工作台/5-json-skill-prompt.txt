```
减少大型不可变数据的响应性开销​
Vue 的响应性系统默认是深度的。虽然这让状态管理变得更直观，但在数据量巨大时，深度响应性也会导致不小的性能负担，因为每个属性访问都将触发代理的依赖追踪。好在这种性能负担通常只有在处理超大型数组或层级很深的对象时，例如一次渲染需要访问 100,000+ 个属性时，才会变得比较明显。因此，它只会影响少数特定的场景。

Vue 确实也为此提供了一种解决方案，通过使用 shallowRef() 和 shallowReactive() 来绕开深度响应。浅层式 API 创建的状态只在其顶层是响应式的，对所有深层的对象不会做任何处理。这使得对深层级属性的访问变得更快，但代价是，我们现在必须将所有深层级对象视为不可变的，并且只能通过替换整个根状态来触发更新：

const shallowArray = shallowRef([
  /* 巨大的列表，里面包含深层的对象 */
])

// 这不会触发更新...
shallowArray.value.push(newObject)
// 这才会触发更新
shallowArray.value = [...shallowArray.value, newObject]

// 这不会触发更新...
shallowArray.value[0].foo = 1
// 这才会触发更新
shallowArray.value = [
  {
    ...shallowArray.value[0],
    foo: 1
  },
  ...shallowArray.value.slice(1)
]

```

Entropy Zero (熵减笔记) 详细功能设计说明书

1. 产品定位与核心价值
      定位： 基于 AI 驱动的“熵减”逻辑，将碎片化信息转化为结构化知识森林的数字大脑系统。
      核心价值： 解决“录入即忘”的知识焦虑，通过 AI 自动化梳理（熵减）降低认知负担，通过可视化森林提供宏观掌控感。
2. 知识录入层 (Input Layer)
      2.1 智能对话沙盒 (The Forge)
      Prompt 驱动生成： 用户输入指令，AI 基于模型能力生成系统化的知识内容。
      标记系统： 所有 AI 生成的内容自动携带 Generated 标签，以便与人工录入区分。
      选择性吸收： 用户可以对生成内容进行勾选，只有被“吸收”的内容才会进入下一步的熵减引擎，未被吸收的保留在对话流中。
      2.2 手动录入 (Manual Entry)
      Markdown 支持： 提供纯粹的 Markdown 编辑器，支持标准语法。
      录入即触发： 手动保存后，系统自动将其视为“原始素材”，启动处理流程。
3. 逻辑处理层 (Entropy Engine)
      3.1 熵减工作流 (Deconstruction & Reconstruction)
      这是系统的关键逻辑，分为以下三个步骤：

逻辑解构： 将原始长文或对话拆解为最小逻辑单元（Atomic Concepts）。
生成索引化笔记 (Leaf Note)：
摘要 (Abstract)： 一句话总结核心内容。
精炼 (Refinement)： 提炼关键结论（Claims）与支撑证据（Evidence）。
关联点 (Hooks)： 自动识别该内容与库中已有知识的关系（如：补充、对立、因果）。
冲突检测： 若新知识与旧知识存在逻辑矛盾，系统将挂起入库流程，弹出“知识冲突”对比框，引导用户进行手动确认（更新、保留或合并）。
3.2 自动制卡 (Auto-Flashcarding)
提取逻辑： AI 根据索引笔记自动生成 Q&A 形式的记忆卡片。
卡片挂载： 卡片作为“树叶”的附属属性，不独立于笔记存在，确保复习时有据可依。4. 视觉呈现层 (Knowledge Forest)
4.1 二维知识森林地图
森林结构：树木 (Tree)： 代表知识分类或主题。
树叶 (Leaf)： 代表具体的索引化笔记。
多维视图切换：领域视图 (Category View)： 按知识本身的学科或类型（如：技术、哲学、艺术）对树木进行聚类排列。
状态视图 (Status View)： 根据新旧程度、复习紧迫性进行排列。
视觉反馈：生长逻辑： 包含树叶越多，树木越粗壮。
健康度： 已内化（复习好）的树叶为绿色，待复习的树叶表现为枯黄或下垂。
4.2 双向溯源系统 (Traceability)
溯源按钮： 每片“树叶”详情页均有一个明显的【源】按钮。
弹窗展示： 点击后，侧边栏或浮窗显示该笔记对应的初始 Markdown 录入稿或 AI 原始对话记录。5. 记忆与反馈层 (Retention Layer)
5.1 间隔复习系统
FSRS 算法集成： 基于自由间隔复习调度算法，精准计算每片树叶的复习时间。
经营压力： 复习任务积累时，整片森林的视觉效果会变得“杂乱”或“干枯”，产生经营紧迫感。
5.2 轻量游戏化经营
修剪模式： 用户点击“经营森林”，系统筛选出今日待复习的树叶。
复习反馈： 采用 Anki 式反馈（难/中/易）。
视觉奖励： 复习成功后，对应的树叶变绿，树木可能触发“开花”或“结果”的特效。6. 搜索与交互 (Interaction)
6.1 意图感知搜索
语义搜索： 基于向量索引，支持用户通过模糊描述寻找相关笔记。
搜索即复习： 搜索结果中会优先高亮显示那些“处于复习临界点”的相关树叶。7. 产品路线图 (MVP 规格)
Phase 1： 实现 Markdown 录入与 AI 熵减生成索引笔记的功能，支持基础复习。
Phase 2： 开发二维森林地图，支持“领域”与“状态”双视图切换。
Phase 3： 完善对话生成沙盒及冲突处理机制，加入森林经营的游戏化动效。
